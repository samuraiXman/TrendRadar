## 🔍 常见问题索引

### Q1: TrendRadar 的架构是什么？
**A:** 分层架构 + 微服务的混合模式
- **分层**：表现层 → 业务逻辑层 → 服务层 → 数据持久化层
- **微服务**：MCP Server 作为独立的 AI 服务
- 详见：[01-架构模式与设计.md](01-架构模式与设计.md) → **架构模式识别**

### Q2: 数据从抓取到推送的完整流程是什么？
**A:** 14 个步骤的完整处理流程
- 初始化 → 抓取 → 规范化 → 过滤 → 权重计算 → 排序 → 推送
- 详见：[03-数据流与处理.md](03-数据流与处理.md) → **典型请求处理流程**

### Q3: 系统的主要瓶颈是什么？
**A:** 网络 I/O（占总耗时的 60-70%）
- 数据抓取: 5-10s
- 多渠道推送: 3-10s（串行）
- 改进方案：使用异步 I/O 实现并行推送
- 详见：[03-数据流与处理.md](03-数据流与处理.md) → **性能瓶颈识别**

### Q4: 如何添加新的推送渠道？
**A:** 在 main.py 中添加 `send_xxx_notification()` 函数
- 步骤：函数模板 → 参数配置 → config.yaml 新增配置项
- 详见：[02-核心组件分析.md](02-核心组件分析.md) → **关键函数清单**

### Q5: 如何优化性能？
**A:** 三个方向的改进方案
- 异步 I/O（8x 加速）
- 算法优化（3x 加速）
- 缓存策略（2x 加速）
- 详见：[03-数据流与处理.md](03-数据流与处理.md) → **总结与改进建议**

### Q6: 系统的单点故障在哪里？
**A:** 主要有 4 个高风险点
1. newsnow API 故障（影响最严重）
2. Webhook 推送渠道故障
3. 配置错误
4. 存储满
- 详见：[03-数据流与处理.md](03-数据流与处理.md) → **单点故障风险分析**

### Q7: MCP 工具如何工作？
**A:** 14 个工具分为 5 类
- 数据查询（4 个）→ 分析工具（7 个）→ 搜索工具（1 个）→ 配置工具（1 个）→ 系统工具（2 个）
- 详见：[02-核心组件分析.md](02-核心组件分析.md) → **MCP 服务模块**

### Q8: 如何部署到 Docker？
**A:** 使用 docker-compose 一键启动
- 支持 AMD64 和 ARM64 架构
- 环境变量覆盖机制
- 详见：[02-核心组件分析.md](02-核心组件分析.md) → **Docker 部署模块**
